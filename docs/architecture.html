Bản thiết kế kiến trúc · v0.1

Mycel

Hệ multi-agent tổng hợp báo cáo và dashboard từ nhiều nguồn dữ liệu rời rạc. Tên lấy từ mycelium — mạng sợi nấm ngầm kết nối cả khu rừng: chạy nền, âm thầm gom dữ liệu, rồi mới trồi lên thành báo cáo.

Storage PostgreSQL · 3 schema LLM vLLM 3B local + cloud Runtime Python 3.11 · Docker Quan trắc OTel → Tempo · Prometheus → Grafana

01 · Luồng dữ liệu

Dữ liệu chảy một chiều qua bốn tầng

Mỗi tầng chỉ đọc tầng ngay dưới nó và ghi lên tầng ngay trên. Không có đường tắt: agent không bao giờ chạm raw hay silver.

02 · Hợp đồng giữa các tầng

Vì sao giữ nguyên raw

Khi logic transform sai — và nó sẽ sai — ta chạy lại từ raw thay vì phải gọi lại provider. Provider có rate limit, có dữ liệu đã bị xoá, có API đổi schema. raw là bản sao ta kiểm soát được.

03 · Tầng AI

Local gánh số lượng, cloud lo suy luận

Mọi lượt gọi model đều đi qua llm/ — không module nào import thẳng SDK của provider. Nhờ vậy đổi model, thêm cache, đặt trần chi phí chỉ sửa một chỗ.

04 · Cấu trúc thư mục

Nhìn tên là biết việc

Module phẳng, một tầng. Khi một module phình to thì tách thành thư mục và giữ nguyên tên: sources/slack.py → sources/slack/{client,parser}.py. Không dựng sẵn tầng trừu tượng khi chưa có gì để bỏ vào.

Mã nguồn
src/mycel/
├─ core/ Config, logging, exception, kiểu dùng chung. Tầng đáy — không import module nào khác.
├─ storage/ Engine, session, repository cho từng tầng. Mọi câu SQL nằm ở đây.
├─ sources/ Mỗi provider một file. Cùng interface: nhận khoảng thời gian, trả bản ghi thô, ghi xuống raw.
├─ pipeline/ Các bước transform. Mỗi bước idempotent — chạy lại hai lần cho cùng kết quả.
├─ pipeline/checks/ Kiểm tra sau mỗi bước: thiếu cột, null bất thường, số đếm lệch. Fail thì dừng, không ghi lên tầng trên.
├─ llm/ Cổng duy nhất tới mọi model. router chọn local hay cloud, cache tránh gọi lại, budget chặn vượt trần.
├─ agents/ manager điều phối, worker thực thi, tools/ là năng lực agent gọi được, prompts/ tách khỏi code để sửa không cần deploy.
├─ jobs/ Hàng đợi: chạy nền, retry khi lỗi, idempotency key, dead-letter khi hết lượt.
├─ reports/ Dựng artifact cuối từ kết quả agent: văn bản, bảng số liệu, dashboard.
├─ scheduler/ Trả lời khi nào chạy. Đẩy việc vào jobs/ rồi thôi, không tự thực thi.
├─ api/ Trigger job thủ công, đọc báo cáo đã sinh, health check. Có xác thực — dữ liệu là nội bộ.
└─ observability/ Log có cấu trúc, trace OpenTelemetry, metrics Prometheus. Mọi tầng gọi vào đây.
Vận hành
evals/ Golden set chấm chất lượng báo cáo. Đổi prompt hay đổi model mà điểm tụt là chặn merge.
deploy/ Config hạ tầng: OTel Collector, dashboard Grafana, init Postgres, inference/ cho vLLM.
config/ Cấu hình theo môi trường và theo nguồn. Bí mật ở .env, không bao giờ ở đây.
migrations/ Alembic. Mỗi thay đổi schema là một revision, không sửa DB bằng tay.
docs/ Tài liệu thiết kế — bao gồm chính trang này.
tests/ Test code, cấu trúc soi gương src/mycel/. Chất lượng báo cáo do evals/ lo.
scripts/ Script vận hành chạy một lần. Không phải nơi để logic nghiệp vụ.

05 · Ràng buộc

Thứ tự phụ thuộc

Mũi tên đọc là “được import bởi”. Không có mũi tên nào đi ngược lên — nếu bạn thấy mình cần import ngược, thiết kế đã sai chỗ nào đó.

06 · Một yêu cầu đi qua đâu

Từ lúc bấm cho tới lúc có báo cáo

Sinh báo cáo mất vài phút và sẽ có lúc lỗi giữa chừng. Vì vậy API không tự chạy — nó đẩy việc vào hàng đợi rồi trả về ngay. Toàn bộ đường đi là một trace.

07 · Nguyên tắc

Quy ước bất di bất dịch

  • Một chiều Dữ liệu chỉ chảy raw → silver → gold. Không tầng nào đọc ngược lên.
  • Agent chỉ đọc gold Agent không bao giờ chạm raw hay silver. Gold là hợp đồng duy nhất.
  • Thêm nguồn không sửa code cũ Một provider mới = một file trong sources/ + một file config.
  • Gọi model chỉ qua llm/ Không module nào import thẳng SDK provider. Đổi model, thêm cache, đặt trần chi phí — sửa một chỗ.
  • Việc lâu thì vào hàng đợi API không chờ LLM chạy xong. Đẩy vào jobs/, trả job id, retry được khi lỗi.
  • Đổi prompt phải chạy eval Báo cáo kém đi không làm test đỏ. Chỉ golden set bắt được.
  • Tên module = việc nó làm Không viết tắt, không tầng trừu tượng dựng sẵn cho tương lai chưa tới.

08 · Chạy thật

Stack vận hành

Một lệnh docker compose up dựng cả app lẫn tầng quan trắc. Thêm --profile local-llm nếu muốn chạy model 3B ngay trên máy.

api Cổng vào

Nhận yêu cầu báo cáo, trả kết quả đã sinh, health check cho load balancer.

scheduler Đồng hồ

Tới giờ thì đẩy việc vào hàng đợi. Không tự thực thi, nên chết không mất job.

worker Tay làm

Rút job ra chạy: sync, transform, sinh báo cáo. Thiếu tay thì --scale worker=N.

vllm Model local

Tuỳ chọn, bật bằng profile local-llm. Không bật thì mọi lượt gọi đi cloud.

postgres Kho dữ liệu

Một database, ba schema. Volume tách rời để nâng cấp image không mất dữ liệu.

otel-collector Điểm gom

App chỉ gửi OTLP tới một chỗ; collector chia về Tempo và Prometheus.

tempo Lưu trace

Một yêu cầu báo cáo là một trace: từ HTTP, qua query gold, tới từng lượt gọi model.

prometheus Lưu metrics

Độ trễ sync, số bản ghi mỗi tầng, token và chi phí theo model, tỷ lệ job lỗi.

grafana Màn hình

Dashboard vận hành, provision từ deploy/grafana/ nên versioned theo code.
