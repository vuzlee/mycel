Config: secrets in .env, everything else in git

One Settings object, read once per process. A value can come from five places; the nearest one wins.

02 · Who wins

Lowest at the left; each layer overrides the ones before it.

Key insight: a container's own env beats .env, which is how compose and Helm point every process at the right host without editing the file.

Details
  • Order is set in Settings.settings_customise_sources; YAML is read by core/settings_source.py.
  • A YAML file that fails to parse is ignored and the defaults stand; doctor and start-up logs are where it shows.
  • MYCEL_ENV may be staging; no staging.yaml exists, so it runs on base.yaml alone.

03 · Where a value goes

.env — not in git

  • Passwords: POSTGRES_PASSWORD, RABBITMQ_PASSWORD
  • Keys: TOKEN_ENCRYPTION_KEY, LITELLM_API_KEY
  • Plugin app secrets: JIRA_CLIENT_SECRET

config/ — in git

  • log_level, db_pool_size, timezone
  • Host models and their prices
  • Per-agent limits: config/agents/*.yaml

Key insight: a YAML key is the Settings field name in lower case, so any of them can still be overridden by an env var of the same name.

04 · Agent files

Each agent's model and limits in its own file; anything left out comes from agents.defaults.

Details
  • Files: analyst, orchestrator, researcher, rewriter, summarizer.
  • Run limits (request_limit, tool_calls_limit) are set only in each agent's file, never in defaults.
  • An unknown key raises ConfigError listing the known ones.

06 · When things go wrong

Not exactly one default host model
start-up fails
A required YAML is missing or not a mapping
ConfigError naming the file
Prod still holds a dev value
doctor: dev values BROKEN
A setting changes at runtime
not seen: settings are read once; restart

Guaranteed / not guaranteed

Guaranteed

  • Settings are frozen: no code changes them mid-run
  • Unknown keys in .env are ignored, not fatal

Not guaranteed

  • A typo in a key is caught: it is silently ignored
