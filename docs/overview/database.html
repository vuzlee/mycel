01 · The layers

Raw in, contract out

02 · Identity

Two kinds of key, never interchangeable

Primary key
  • Set by Postgres
  • Means nothing outside this database
Natural key
  • Set by the source: (source, issue_key), (source, worklog_id)
  • An edited issue keeps it → re-sync updates, never duplicates
  • source is in the key: Jira will not be the last tracker
  • bronze uses Jira's own id as its primary key
  • No foreign keys between layers
  • Each layer rebuilds from the one below
  • NULL is a real state: unassigned, unestimated, no due date, not resolved
  • Never coerced to 0
  • Always NOT NULL: keys, kind, status, title, sync timestamps

04 · silver

The same columns, a different obligation

silver.work_item · silver.worklog
  • Same columns as gold, below
UNIQUE uq_silver_work_item_natural_key (source, issue_key)
UNIQUE uq_silver_worklog_natural_key (source, worklog_id)
INDEX ix_silver_work_item_project_updated · ix_silver_work_item_due_at · ix_silver_worklog_project_started

Identical is the expected state, not a duplication to clean up.

  • Silver answers to the source. Jira adds a field, renames a status — this table changes.
  • Gold answers to the question. A new dashboard block — that table changes.
  • One source, one sentence. Both describe the same table today, so etl/promote.py is the identity function.
  • What it buys: a place for the difference when a second tracker arrives.
  • What it costs: every sync writes each row twice.
  • silver.message dropped in migration 0005

07 · Reading the columns

Timestamps that look alike

PairDifference
fetched_at / updated_at When we pulled it / when Jira recorded the change. The second is the next sync's high-water mark; the first is only for forensics.
resolved_at / worklog.started_at The pair that matters most. Jira stamps resolved_at at the moment of the API call, so a back-filled project has one day on which everything finished. started_at is declared by the person logging, so it can be back-dated — which is why every time-shaped chart is drawn from worklogs.
time_spent_seconds, in two tables On work_item it is Jira's total for the whole issue. On worklog it is one entry. Summing the second by issue gives the first — unless someone overrode it by hand, in which case Jira's own total wins.
id / natural key Our row number / the source's ids. Only the second survives a rebuild.

08 · Types

Why each type was chosen

TypeMeansChosen because
bigint64-bit integer A project's logged seconds, summed, exceed 32-bit range
serialauto-incrementing int Internal primary key; PostgreSQL does the counting
varchar(n)bounded string Anything longer than n is malformed — reject it at the database
textunbounded string Human-written content; no slower than varchar in PostgreSQL
jsonbparsed JSON Queried in place, without deserializing in Python
timestamptzinstant with offset Moving the server does not shift the numbers
