Part 1

The idea

1.1 · Data flow

Data flows one way through four layers

  • Each layer reads only the one below it
  • Agents never touch bronze or silver
  • Only Jira is stored; mail and calendar are read live when asked
  • Key: bold line = the only way data reaches the AI · dashed = control and monitoring, not data
  • Data axis: plugins → bronze → etl → silver → gold, on a timer, minutes
  • Request axis: route → service → queue → worker → domain (Part 2)
  • The two meet only at gold

1.2 · The contract between layers

Four schemas, one direction

  • Bad transform → re-run from bronze, no new Jira calls
  • Providers rate-limit and change; bronze is the copy we control
SchemaHoldsWritten byRead by
bronzethe provider's payload, untouched, append onlyplugins/jira/fetch.pyetl/normalize.py
silvertyped columns, UTC times; changes when the source changesetl/normalize.pyetl/transform.py

Part 2

Code flow

2.1 · Each layer's responsibility

Who does what in a request

  • Route in api/routes/: validate, call a service that queues the job
  • Module in domains/: what the worker runs for that job, chaining services
  • The two share a name (chat.py), not a call: api/ may not import domains/
Layer May May not
api/app.py Create the app, mount each router, middleware, observability Hold endpoints · hold business logic
api/routes/·.py Receive the request, validate, call a service (which queues the job), return the response SQL · call an LLM · business if/else
domains/·.py Define the order of the steps, calling services in turn Do a service's work · import a FastAPI type · know who called it
services/ One single job, done end to end, reusable across domains Call a domain, an agent or a route; another service is fine
etl/ agents/ The heavy lifting: transforms, reasoning, artifact building Read the HTTP request · write SQL by hand
infra/ Every SQL statement, session and transaction Hold business decisions
  • Domain = the steps of one job; service = one reusable step
  • domains/chat.py: prepare → orchestrator → settle into app.turn
  • plugins/jira/sync.py: fetch → transform (checks inside) → queue the index job

2.2 · The life of a request

From the question to the stored answer

  • An answer takes minutes and may fail halfway
  • So the API queues it and returns at once
  • The whole path is one trace

2.3 · Who is calling

2.4 · Dependency order

Dependency order

  • Arrow points to the importer: core → infra = infra imports core
  • Left imports nothing, right imports everything
  • Need an import against the arrows? The design is wrong; tests/test_layers.py fails the build

The state Redis on 6379 is not persisted. If it restarts or is flushed:

LostWhat happens
Job results and event streamsNothing visible: polls and reloads fall back to app.turn in Postgres
Job budgetsA job retried afterwards starts with a full ceiling again
Delivery counts and job claimsA job that kills its worker gets a few more tries; a duplicate delivery could run once more
Rate-limit windowsEvery limit starts over
Unconfirmed draftsThe person asks for the draft again

The cache Redis on 6380 can be flushed at any time; it only costs recomputation.

4.1c · Silent traps

Six things that raise no error when they are wrong

TrapWhat happens
BaseHTTPMiddleware
blocks SSE		 It buffers the response, so tokens arrive in one lump at the end. Looks like a slow model. The request-id middleware is therefore pure ASGI
Traces break at the
process boundary		 contextvars do not cross a process. Without inject()/extract() in the message headers you get two unrelated traces, and nothing errors
setup_tracing()
runs too late		 Called after instrument_app(), spans fall into an empty provider and disappear — silently
Budget counted at
the call site		 Sub-agent usage does not roll up on its own. Only runner.run charges; delegate passes usage=ctx.usage, or a three-agent job is billed four times
Pool sized
per process		 The limit is max_connections across all processes, not per one. It only fails under load
A hung pod with an
open port looks healthy		 Self-healing is only as correct as the probes. vllm needs a startupProbe — the model takes minutes to load

Summary

Nine rules that do not bend

RuleMeans
One directionbronze → silver → gold, never back
Agents read gold onlyfor Jira data, gold is the only contract; mail, calendar, web and uploads are read live by tools
New source, no editsa folder in plugins/ + a registry line
Models through one placethe gateway or a person's endpoint, built in model_builder.py
Slow work on the queuethe API returns a job id, never waits for a model
Prompt changed → run evalsa worse answer turns no test red
Thin routes, thick domainsslow work is queued and runs in domains, so the scheduler can start it without the API; quick reads answer at once
Same images everywhereapp and ingest, tagged by commit SHA; only env differs
Name = jobno abbreviations, no layers for a future
