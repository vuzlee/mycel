Part 1

The idea

Data from scattered sources flows one way through four layers and ends as an answer. Understand this part and you understand what the system does.

1.1 · Data flow

Data flows one way through four layers

Each layer only reads the layer directly below it and writes to the one directly above. No shortcuts: agents never touch bronze or silver.

  • Data axis: plugins → bronze → etl → silver → gold, on a timer, minutes
  • Request axis: route → domain → service, seconds (Part 2)
  • The two meet only at gold

1.2 · The contract between layers

Why bronze is kept untouched

  • One source today: silver and gold hold the same columns
  • Bad transform → re-run from bronze, no new Jira calls
  • bronze is the copy we control: providers rate-limit, delete, change schema

Part 2

Code flow

Which layers a request passes through, which layer calls which, and which module may import which.

2.1 · Each layer's responsibility

Who does what in a request

  • Route in api/routes/: validate, hand off
  • Module in domains/: chains services
  • Nothing below the route knows HTTP
Layer May May not
api/app.py Create the app, mount each router, middleware, observability Hold endpoints · hold business logic
api/routes/·.py Receive the request, validate, call a domain, return the response SQL · call an LLM · business if/else
domains/·.py Define the order of the steps, calling services in turn Do a service's work · import a FastAPI type · know who called it
services/ One single job, done end to end, reusable across domains Chain other services together — that is the domain module's job
etl/ agents/ The heavy lifting: transforms, reasoning, artifact building Read the HTTP request · write SQL by hand
infra/ Every SQL statement, session and transaction Hold business decisions
  • Domain = the chain; service = one link
  • domains/chat.py: enqueue → worker → orchestrator → app.turn
  • plugins/jira/sync.py: fetch → transform → check

2.2 · The life of a request

From the question to the stored answer

  • An answer takes minutes and may fail halfway
  • So the API queues it and returns at once
  • The whole path is one trace

2.3 · Who is calling

A cookie, and one row that can be deleted

  • Every request names a person: the data is the team's own
  • Browser holds a token; server keeps the matching row
Decision Why
No passwords: Google or an emailed code Mycel already lives on Google, so a password is one more secret to leak and reset. The id token is checked against Google's keys; a code works once.
An opaque token, not a JWT Revoking a JWT needs a server-side list of revoked ones — that list is app.session with extra steps. So it is that table without them, and logging out deletes the row.
Expiry checked on read The database holds expires_at and enforces nothing. A session one second past expiry has to read as gone before any sweeper runs.
HttpOnly · SameSite=Lax A token a page can read is a token a cross-site script can steal. Lax keeps it off cross-site POSTs, which is the CSRF defence this needs while every mutating call comes from the app's own pages.
Depends(current_user),
not middleware		 It reaches the OpenAPI schema and mypy checks it. A middleware that sets a request attribute does neither.
  • Every security decision: services/auth.py
  • api/routes/auth.py only turns it into HTTP
  • Which projects may this person read? → services/permission.py
  • Answer comes from app.membership, filled from Jira
  • Agent queries: same list, enforced by Postgres row security

Part 3

Directory layout

One job per folder, obvious from the name. The last section goes deep into the AI layer — the easiest place to get wrong.

3.1 · Directory layout

The name tells you the job

  • Flat, one level deep; a big file becomes a same-name folder
  • A provider a person connects = a folder in plugins/

src/mycel/

api/Routes, middleware, serves the web app. Parses and authorises; never runs a model.
services/One job each, called from api, worker, plugins and tools: enqueue, permission, sealing, model catalog.
domains/What a queued job does: chat, ingest, index, sync, key checks; the Knowledge chip. Knows nothing about HTTP.
agents/Orchestrator, analyst, researcher; shared tools, prompts, and the runtime that opens a model.
plugins/One package per provider (Jira, Google): HTTP client, OAuth, tools, sync, doctor probe.
etl/bronze → silver → gold and the checks between; uploaded files into passages.
queue/RabbitMQ: publish, consume, retry, dead-letter.
scheduler/Timers: outbox relay, one sync per plugin, sweeps.
infra/Postgres, Redis, Qdrant, MinIO, SMTP, the shared HTTP client. All SQL lives here.
llm/Model specs, prices and the per-job cost budget. Value types only.
events/What a run publishes while it works.
core/Settings and shared types. Imports no other layer.
observability/Traces to Langfuse, Prometheus metrics.
doctor/What is configured, broken, or off on purpose.
mcp/Tools on external MCP servers.
lifecycle.py · worker/At the root: process start/stop, and job dispatch (worker/handlers.py). Each wires every layer, so inside one they would import upward.

repo root

web/The React app, served by the API at /app. src/api/ one file per backend area; components/home/ the landing page.
migrations/Alembic. A downgrade outside a _test database is refused.
config/Environment YAML, the gateway, MCP servers.
evals/Golden questions run by hand against real models.
tests/Code tests; only ever on a _test database.
scripts/Run, deploy, doctor, sync, gateway key.
deploy/Helm chart, monitoring.
docs/This handbook.

Six things that raise no error when they are wrong

They simply behave wrongly, which is worse: nothing turns red, so nobody looks.

4.3 · On the cluster

Kubernetes on-premise

  • Runs in-house; only the final model call leaves
  • docker-compose.yml = dev; deploy/helm/ = cluster
  • Same image, same env vars, no if env == "prod"
  • Four app pods on minikube + ConfigMap, Service, Ingress, migration hook
  • Stores stay outside, at host.minikube.internal
  • Not built on purpose: Argo CD, Harbor, autoscaling, StatefulSets
Requirement Solution Easy to get wrong
The API can scale Deployment.replicas — many pods behind one Service —
A dead pod comes back kubelet restarts the container; the Deployment recreates a lost pod A hung pod with an open port looks healthy to K8s. Self-healing is only correct when the probes are
More traffic adds pods Not built. worker.replicas is a number in values There is no load. An HPA on CPU is ten lines that mean nothing, and the measure that would mean something is RabbitMQ queue depth through KEDA — a second control plane for a problem nobody has
Services can reach each other Service — one stable DNS name, load-balanced already —
Reproducible deploys Helm — a versioned chart; the same chart + the same values gives the same result version is the chart's, appVersion is the image's commit SHA. Rolling back the chart does not roll back the code
Automated deploys Not built. helm upgrade --install, run by hand or by CI Argo CD answers “what is running, who changed it, when” — and with one person, one cluster and one branch, git log already answers it. Its prune is also a live hazard: one wrong line in values deletes a PVC
Private container images Not built. minikube image load — no registry at all The only part of Harbor worth having here is the proxy cache, which registry:2 does in one container. Tag = commit SHA, never latest: two pods with the same manifest would otherwise run different code

4.4 · Status

What exists and what does not

Most of this page now describes a running system. The table below draws the line between what runs and what is still an intention.

Item Status
Directory skeleton · layer conventions Built — the modules exist, docstrings state their responsibilities
docker compose · observability Running: postgres, rabbitmq, redis, qdrant, minio. Behind a profile: api, vllm, prometheus, loki, alloy, grafana. Dropped: kafka (JVM)
CI · build image Workflows exist: lint, type check, migrations, tests; builds an image tagged by SHA
Helm chart on minikube Built — four app pods (api, worker, scheduler, ingest) and a migration hook; CI renders it. There is no cluster beyond minikube to deploy to
plugins/ — Jira, Google Built — one interface and a registry; each person connects with OAuth. The Jira sync reads each project on a connected person's token. Writes are off unless JIRA_WRITE_ENABLED turns them on
etl/ — bronze → silver → gold Built — normalize.py and promote.py, driven by etl/transform.py under an advisory lock
agents/ · chat Built — orchestrator, analyst, researcher (web + mail), summarizer; an answer is markdown kept in app.turn
app/ — sign-in and Ask Built — Google or an emailed code, an opaque session cookie. Chat is the main screen; the old report page went once an agent could answer it
Plugins beyond Jira and Google Slack and Confluence are still intentions. Adding one is a folder under plugins/ and a line in the registry
Project membership Built — Jira says which projects each person may browse; gold rows are filtered by Postgres row-level security
Vector search · librarian infra/vectors/ backs rag_search over uploaded documents
LLM cache llm/cache.py is written and has no caller
evals/ — golden set Six cases in evals/golden/, run by hand — not in CI
Model local 3B The specific work it carries is undecided. With no real high-volume work, the local layer can be dropped entirely

Summary

Nine rules that do not bend

If only one part of this page sticks, make it this one.

  • One direction Data only flows bronze → silver → gold. No layer reads back upwards.
  • Agents read gold only Agents never touch bronze or silver. Gold is the only contract.
  • Adding a source does not change existing code A new provider = one folder in plugins/ + one line in the registry.
  • Models are called only through llm/ No module imports a provider SDK directly. Switching models, adding a cache, setting a spend ceiling — one change.
  • Slow work goes on the queue The API does not wait for an LLM. Push to queue/, return a job id, retry on failure.
  • Changing a prompt means running the evals A worse answer does not turn a test red. Only the golden set catches it.
  • Thin routes, thick domains If api/ could be deleted entirely and scheduler would still sync and answer, the layers are in the right place.
  • One image for every environment Built once, tagged by commit SHA. Only environment variables differ.
  • Module name = what it does No abbreviations, no abstraction layers built for a future that has not arrived.
