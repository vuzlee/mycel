Flow

What the model sees

  • Each model request is the prompt plus the run so far
  • Numbered: date, shrink, summarise, call; web_search adds recency on the side
  • Hover a box for its file · click to open it
Why
  • A model knows nothing past its training and reads only what is sent each time
  • Long runs fill the context and fail; these four steps keep it current and small

Words

WordMeans
promptthe fixed instructions sent before the conversation; it names the tools and columns that exist
token (model)the unit a model counts text in; about 4 characters
token capthe most tokens one agent run may use: total_tokens_limit in config/agents/*.yaml
tool resultwhat a tool returned to the model; old web results shrink to one line
runone agent's work on a turn: the model and its tool calls until an answer
side arrowan unnumbered arrow in a flow figure: a lookup a step makes on the way, not a step of its own

Key facts

WhatValue
datethe question (not the fixed prompt) starts with today's date in the asker's zone; a small model could not miss it
recencyweb_search sends day / week / month / year as Tavily's time_range
old resultsweb results older than the last 2 rounds become one line: urls kept, text dropped; other tool results stay whole
compactpast 75% of total_tokens_limit a model call summarises the middle of the run
measuredAI-news question: 333k tokens and a failure → 110k tokens and an answer

When it goes wrong

CaseWhat happensWhere
model ignores the daterecency still filters by timeagents/tools/web_search.py
a search stalls or returns 5xxa stall (20 s timeout) or 5xx is resent once at once; still failing → that query comes back empty with a warning, the others kept; every query failed → the tool fails, the job is parkedagents/tools/web_search.py
summary call failsthe run fails with it (retried if the model error is transient)agents/core/compact.py
cap reached anywaythe run stops as runawayagents/core/exceptions.py
