Mycel on AWS

  • The whole product on one EKS cluster, up a few hours, then deleted
  • Before a demo: aws up · anyone opens https://mycel.sbs · after: aws down
  • Only the owner reaches Grafana and the stores, through a tunnel
  • Hover a box for its files

1 · The design

Words in the figure

WordMeans
EKSKubernetes run by AWS: AWS keeps the control part, you rent the machines
EC2 · nodea rented virtual machine · here the one machine the pods run on
podone running copy of a program image
VPC · subnetyour private network in AWS · a slice of it in one data centre
NATa paid gateway for private machines to reach the internet; skipped, the node has a public address
Helm chartan install package of Kubernetes objects; two here: mycel and mycel-stores
emptyDira pod's scratch folder, gone with the pod: nothing is kept between sessions
port-forwarda tunnel from your laptop to one pod through the Kubernetes API
Terraform · statecloud resources written as files · the record of what it made, so it can delete it
Lambda · SNSa function AWS runs on a schedule · a topic that sends mail
Route 53 · ACM · ALBAWS's DNS · free HTTPS certificates · the public HTTPS load balancer
LB controllera pod that reads the app's Ingress and makes the ALB for it
LiteLLMone door to every AI model; holds the provider keys
SSOsigning in to AWS through a portal, short sessions, no stored keys: aws sso login --profile mycel

3 · One session

CommandDoes
aws sso login --profile mycelsign in first; every command stops without it
stack.sh aws upstep 1
stack.sh aws forwardGrafana (and the app) on localhost; a dropped tunnel restarts
stack.sh aws extend <h>expiry = now + h, at most 12
stack.sh aws downstep 3; safe to run again
stack.sh aws status [--bill]what runs, expiry; --bill the month's cost ($0.01 a call, a day late)
